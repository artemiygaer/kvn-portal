# Проверки модуля Xray

Проверки выполняются в WSL. Для systemd, ingress и проверки закрытия порта
используется отдельная Debian 13 VM (1 vCPU, 1 ГиБ). Рабочие серверы
не используются. Тестовые пользователи, ключи и издатель пакетов — синтетические.

| Проверка | Свидетельство |
| --- | --- |
| VLESS TLS, Reality TCP, Reality xHTTP | `tests/v5/xray_protocol_e2e.py`, `output/v5-lab/phase6-xray-protocol-r9.log`: три действительных HTTP-запроса через клиент Xray в изолированной сети Docker. Отдельный `phase6-xray-ipv4.log` подтверждает IPv4-only, оба прогона exit=0. |
| Внешний Reality и self-steal | Тот же E2E проверяет HTTPS fallback обычного клиента, неизменность ключа и отсутствие лишних портов. `tests/v5/test_xray.py` отдельно проверяет явное переключение режима и отсутствие 8443 в настройках Xray. |
| Рендер VLESS и подписки | `tests/v5/test_xray.py`: base64, параметры Reality/xHTTP, исходный SNI при подключении по IP, выдача только доступных профилей. Контракт HAPP/Karing сверён с источниками в `UPSTREAM.md`; запуск их графических приложений в эту проверку не входит. |
| Установка пакета без запуска | `tests/v5/test_packages.py` проверяет multipart и GitHub API/CDN на двух тестовых сетевых источниках. В реальном Debian подписанный офлайн-пакет принят без рабочего конфига, процесса или нового порта (`phase6-debian-r3.log`). Публикация и загрузка готового релиза из GitHub — отдельный финальный тест. |
| Подтверждение образа | `tests/v5/test_xray.py` проверяет digest, платформу, список слоёв и запрет изменяемых тегов. Артефакт ядра содержит код адаптера и unit, но не образ, ключи и конфигурацию VPN (`tests/v5/test_installer_artifact.py`). |
| Транзакция версии | `tests/v5/test_network.py` проверяет отказ подготовки, ошибку health, восстановление после прерывания, успешное подтверждение и отображение старой версии во время операции. Включение, отключение и обновление доступны через узкий Unix RPC; тесты аутентификации в `tests/v5/test_lifecycle_rpc.py`. |
| Debian: порты, отключение и откат | `output/v5-lab/phase6-debian-r8.log`, exit=0: TLS:2443 по обеим семьям IP, Reality:443, обычный сайт и вход в портал:8443 с проверкой CA. Кандидат — другой подписанный пакет с онлайн-получением того же digest образа; намеренный отказ health после запуска нового контейнера восстановил старую подписанную версию и сохранил SHA-256 настроек и ключа. После disable прямые порты и SNI-маршрут исчезли; сайт и админка остались доступны. |

Ранний прогон r3 зафиксировал настоящий запуск Xray, но прежний предел
ожидания готовности не позволил завершить тест. R6 закончился до начала
fixture: после остановки WSL/QEMU Debian не успел загрузиться к SSH-дедлайну.
В r7 успешно открылись сайт и админка с проверкой учебной CA, а
проверка извне выявила IPv6 на прямом порту `2443` при `0.0.0.0`.
По документации XTLS это dual-stack: r8 учитывает обе семьи в плане.
Конкретный IPv4 проверяется отдельным прогоном Docker E2E в WSL.

В финальном прогоне на Debian 13 подписанный пакет издателя установлен через
панель, Docker подготовлен отдельной подтверждённой задачей. Reality TCP
включён и отключён через HTTPS: прямой порт 2444 освободился, настройки
сохранились, службы портала остались активны (exit 0). Использована только
изолированная VM; этот прогон не заменяет проверки доступности у операторов.

Инженерные проверки WSL: архитектурный контроль и `compileall` exit=0;
96 тестов v5 exit=0; 47 legacy-тестов exit=0 (1 явный skip старого
Docker E2E). `git diff --check` и проверка границ v4.2 — exit=0.
