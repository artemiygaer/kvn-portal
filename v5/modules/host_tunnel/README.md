# Туннели хоста

WireGuard (`wg0`, UDP/51821) и AmneziaWG (`awg0`, UDP/51820) — отдельные подписанные модули. Подготовка и установка пакета не создают интерфейс и не запускают unit. Страница «Модули» показывает версии текущего ядра, инструментов и поддерживаемые профили по кнопке диагностики.

На Debian для WG нужен `wireguard-tools` и модуль `wireguard` текущего ядра. Для AWG нужны отдельные `awg` и модуль `amneziawg`; сборка требует заголовки **загруженного** ядра. AWG 3.1 требует одновременно совместимых kernel и tools. Встроенный установщик ядра не устанавливает Docker, WireGuard, AWG, заголовки или компилятор. Туннель использует nftables, не добавляя правила в чужие таблицы.

После установки подписанного пакета настройте его с сервера:

```bash
cd /usr/local/lib/kvn-v5
sudo python3 -m v5.core.lifecycle.manage tunnel-status wireguard
sudo python3 -m v5.core.lifecycle.manage init-tunnel wireguard
sudo python3 -m v5.core.lifecycle.manage enable wireguard
```

Для AWG замените `wireguard` на `amneziawg`. `init-tunnel amneziawg` сразу выбирает 3.1; флаг `--modern` оставлен для совместимости прежних команд. Без поддержки нужных параметров tools и ядром запуск отклоняется, а не переключается на legacy. `init-tunnel` создаёт ключ только один раз и отказывается перезаписывать существующие настройки. Явно перенесённый legacy не переключается молча: смена профиля требует отключения туннеля и повторного экспорта AWG-клиентов. WG не затрагивается.

По умолчанию клиент получает маршрут только к подсети туннеля. Для IPv4-интернета укажите интерфейс выхода (например `ens3`) и разрешите порт/пересылку в действующем firewall. После создания настроек можно отдельно включить пересылку IPv4 на карточке модуля с явным подтверждением. Это общесистемное изменение: переключение `ip_forward` может сбросить другие параметры IPv4 ядра. Служба портала включает его после перезагрузки; остановка или удаление модуля не отключает пересылку, поскольку её могут использовать другие службы. Сторонние правила firewall портал не ослабляет. NAT ограничен подсетью туннеля и выбранным исходящим интерфейсом; IPv6 endpoint не означает выдачу IPv6-маршрута клиенту.

Закрытые настройки `/var/lib/kvn-v5/modules/<модуль>/settings.json` изменяются атомарно через `configure-tunnel <модуль> <файл 0600>` из закрытого каталога. В активном туннеле разрешена смена только списка peers: она применяется `syncconf` без остановки интерфейса. Адрес, ключ сервера, MTU, egress и профиль меняются только после отключения. Отключение удаляет свой интерфейс, закрывает UDP-порт и оставляет настройки на диске.

Карточка пользователя выдаёт `.conf` и QR после подтверждения права. Отзыв убирает peer, но не удаляет ключ и адрес клиента; повторная выдача сохраняет профиль. `.conf` передавайте лично: он содержит закрытый ключ клиента. Подписка HAPP эти файлы не включает.
