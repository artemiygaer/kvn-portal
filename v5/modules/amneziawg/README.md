# AmneziaWG

Начальные настройки выключенного модуля можно создать в панели. Существующие
ключи при повторном запросе не заменяются. Если исходящий интерфейс не задан,
клиенты получают доступ только к подсети туннеля; для выхода в интернет также
требуется включённая на сервере пересылка IPv4. Новая настройка использует 3.1.

AmneziaWG слушает UDP/51820 (`awg0`), отдельно от WireGuard. Новые установки v5 используют профиль 3.1 по умолчанию. Требуются актуальные совместимые tools и kernel module: при отсутствии поддержки 3.1 запуск отклоняется, автоматического отката к legacy нет. `HeaderProtectionKey` хранится только в закрытых настройках и экспортируется лишь в выданный клиентский профиль.

Legacy остаётся форматом совместимости при явном переносе старых конфигураций. Перевод старого туннеля на 3.1 требует подтверждённой смены профиля и повторного экспорта всех клиентов; обновление панели не меняет его автоматически. Более новые версии 3.x допускаются после проверки ABI и реального прогона, а не только сравнения строки версии.

Для проверки 3.1 используем [исходники модуля `v3.1.20260906`](https://github.com/amnezia-vpn/amneziawg-linux-kernel-module/tree/v3.1.20260906) и [tools `v3.1.20260812`](https://github.com/amnezia-vpn/amneziawg-tools/releases/tag/v3.1.20260812). В ранних сборках обработка ключа могла завершаться ошибкой ([upstream issue 216](https://github.com/amnezia-vpn/amneziawg-linux-kernel-module/issues/216)). Номер, который показывает `modinfo`, не гарантирует совместимость: он задаётся при сборке. Диагностика проверяет параметры tools, применяет синтетический профиль к временному выключенному интерфейсу без IP и UDP-порта и сверяет возвращённые ядром настройки.

См. [диагностику и настройку туннелей](../host_tunnel/README.md).
