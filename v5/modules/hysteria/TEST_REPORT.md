# Проверка Hysteria2 v5

Стенд: локальный WSL/Docker и отдельный Debian 13 в QEMU. Пакет подписан
учебным ключом, доверие клиента проверяется синтетической CA. Рабочие
серверы и релиз v4.2 не используются.

## Подтверждено

- WSL r6: архитектура (9 границ), compileall, 115 тестов v5, 25 тестов
  совместимости proxy/export — exit=0. Проверены UDP/TCP-матрица,
  фильтрация разрешений, экспорт с DNS SNI по IPv4, атомарная замена пары
  и запрет подмены registry/digest.
- WSL/Docker: штатный клиент v2.13.0 из закреплённого образа передал HTTP
  через QUIC с отдельного клиентского netns по JSON-профилю и по URI.
  Неверный пароль, недоверенная CA, чужой SNI и отключённая учётная запись
  отвергнуты. Новый сертификат принят тем же контейнером, прежняя CA
  отвергнута. UDP-порт подтверждён закрытым после остановки. Exit=0,
  журналы phase8-wsl-quic-r2.log и phase8-wsl-quic-r3.log.
- Debian 13 r2: образ по зафиксированному digest, бинарник v2.13.0;
  после подписанной установки UDP/443 закрыт, HTTPS TCP/443 и TCP/8443
  доступны. При занятом UDP/443 попытка включения отклонена до записи
  операции; состояние nginx и Docker не изменилось.

На первом включении r2 завершился ошибкой: Docker bridge на учебной
однопроцессорной VM переходил в forwarding 67,59 с, а проверка отводила
30 с. В последующем откате истекли таймауты systemctl. В r4 окно готовности
увеличено до 120 с, проверки образа, публикаций и UDP-listener не сняты.
На r4 контейнер успел запуститься; отказ был в пятисекундном Docker exec
для чтения UDP-таблицы. Откат завершился успешно. r5 читает UDP-таблицу
напрямую в namespace PID из Docker inspect, сверяет порт, состояние и UID.
В WSL это работает даже с пустым capability bounding set; повторный
QUIC, hot TLS и закрытие порта прошли (phase8-wsl-quic-r3.log).

## Клиент и перезагрузка на Debian 13

На Debian r5 подтверждены UDP/443 и реальный HTTP через QUIC из
клиентского namespace, по JSON и URI. Чужие пароль, CA, SNI и выключенная
учётка отклонены. Сайт TCP/443, админка TCP/8443 и nginx-конфигурация
сохранены; лишние UDP/11443 и IPv6 UDP/443 не открылись. На Debian
принят переизданный сертификат без замены контейнера, прежняя CA отвергнута.
Отключение остановило контейнер; проверка экспорта прервалась на неверном
типе SQLite-флага в драйвере. С исправленным драйвером на том же состоянии,
без переустановки, проверены: UDP/443 закрыт, профиль не выдаётся, настройки
совпадают с применёнными до отключения, HTTPS TCP/443 и 8443 работает.
r5 подтвердил новый boot ID и выключенное состояние, но холодный
`docker inspect` на re-enable не ответил за 25 с; откат завершился.
r6 повторяет только транспортный сбой до общего дедлайна. На том же
новом boot ID проверены закрытый UDP, сохранённые ключи и HTTPS; после
повторного включения прежний URI передал трафик. Повторный disable снова
закрыл UDP. Менялись только два файла проверки готовности, без пересоздания
пакета, учётных данных и TLS-пары (phase8-debian13-reboot-r6.log).

| Точка проверки | TCP/443 (сайт), TCP/8443 (вход) | IPv4 UDP/443 | Другие UDP-порты |
| --- | --- | --- | --- |
| Подписанная установка, TLS отсутствует | Bootstrap админки доступен | закрыт | не открываются |
| После активации с TLS | HTTPS проверен | рабочий QUIC | UDP/11443 и IPv6 UDP/443 закрыты |
| Disable, затем новый boot ID | HTTPS проверен | закрыт | не открываются |
| Re-enable со старым профилем | HTTPS проверен | рабочий QUIC | изменений нет |

Дополнительный прогон на Debian 13: подписанный пакет издателя установлен
через панель; с синтетическими пользователем и доверенной тестовой CA модуль
включён и выключен через HTTPS, UDP/443 освобождён, настройки сохранены.
После проверки прежняя конфигурация шлюза и системное доверие восстановлены.
Это проверка выделенной VM, не гарантия доступности в сетях операторов.
На отдельной Debian 12 тот же подписанный модуль также прошёл включение и
выключение через HTTPS с тестовой CA: UDP/443 закрыт, настройки сохранены,
конфигурация шлюза и доверие восстановлены. Клиентский трафик в этом
дополнительном прогоне не измерялся.

Быстрый QUIC-прогон в локальном WSL:
`sudo env PYTHONPATH=. python3 tests/v5/fixtures/check_hysteria_docker.py`.
Он требует локального образа по digest и временно создаёт клиентский
namespace и контейнер; systemd и reboot не проверяет.

Воспроизведение на выделенной VM: `python3 -m tests.v5.hysteria_lab_e2e
22058 /путь/к/kvn-portal-v5-installer.tar.gz` одной строкой. Скрипт проверяет
идентификатор стенда, контрольную сумму ядра и учебный модуль, затем
запускает отдельный клиентский namespace. Журналы в `output/v5-lab/`:
`phase8-unit-r6.log`, `phase8-legacy-r6.log`, `phase8-debian13-e2e-r2.log`,
`phase8-debian13-e2e-r4.log`, `phase8-debian13-e2e-r5.log`,
`phase8-debian13-reboot-r5.log` и `phase8-debian13-reboot-r6.log`.
