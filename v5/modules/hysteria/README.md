# Hysteria2 в KVN v5

Подписанный модуль устанавливается выключенным. Для запуска нужны Docker
Engine, активная доверенная TLS-пара зарегистрированного имени или IPv4 и
хотя бы один разрешённый пользователь. Установка пустого портала не тянет
образ и не запускает Docker. Включение открывает только выбранный IPv4
UDP-порт (по умолчанию 443), не меняя TCP/443 и TCP/8443. Доступ снаружи
также зависит от правил облачного firewall. IPv6, port hopping, встроенный
speed test и HTTP API статистики не включаются.

- Проверенный [Hysteria2 v2.13.0](https://github.com/HyNetworks/hysteria/releases/tag/app/v2.13.0),
  образ `docker.io/tobyxdd/hysteria` по digest для своей архитектуры:
  amd64 `sha256:5ed85e7f01de4ea6b8ce66ed6e69527e59c29784138f3f9d933d81024fc5c69f`,
  arm64 `sha256:6722e2a6c46d2b6e041af86b2ac8ceaf57c672ca55738a37bea1af6e56cfb364`.
- Создайте и изменяйте настройки на странице модуля при выключенном сервисе.
  Выберите зарегистрированное имя или IP, UDP-порт и при необходимости
  Salamander; секрет создаётся на сервере и не показывается в панели.
  Смена адреса, порта или режима требует повторной выдачи конфигураций.
  Существующие учётные данные сохраняются.
- Нативный конфиг и [URI Hysteria2](https://v2.hysteria.network/docs/developers/URI-Scheme/)
  доступны только для разрешённых пользователей активного модуля. Экспорт
  по IPv4 сохраняет DNS SNI. Для сертификата с IP SAN endpoint обязан
  совпадать с этим IP. Проверка TLS не отключается.
- Контейнер непривилегированный: read-only, без capabilities и Docker
  socket. Сертификат и ключ публикуются одним файлом только в отдельный
  read-only bind mount. При успешном ACME-прогоне одноразовая служба
  переносит действующую пару; сам Hysteria2 перечитывает её на новом
  handshake. [Документация TLS Hysteria2](https://v2.hysteria.network/docs/advanced/Full-Server-Config/#tls).
- Отключение освобождает порт и не удаляет настройки или пароли.
  Salamander включается явно: без совпадающего пароля у клиента
  соединение не установится.
