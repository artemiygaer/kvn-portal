# Установка и обслуживание v5

Нужны отдельный Debian 12/13 с systemd и root-доступом по SSH, публичный IP,
TCP/80, 443 и выбранный порт панели (по умолчанию 8443) в firewall сервера и провайдера. Для DNS-имён заранее
направьте A/AAAA на сервер. На минимальной системе установите штатные `curl`
и `ca-certificates`. **Не запускайте установку поверх v4.2.**

## Чистая установка

Когда готовый v5-релиз опубликован, получите его точный тег и SHA-256
установщика из доверенного объявления. В интерактивной root-сессии SSH:

```bash
(
  set -eu
  umask 077
  read -r -p 'Тег v5: ' tag
  read -r -p 'SHA-256 установщика: ' sha
  [[ "$tag" =~ ^v5\.[0-9]+\.[0-9]+(-[A-Za-z0-9.-]+)?$ ]]
  [[ "$sha" =~ ^[0-9a-fA-F]{64}$ ]]
  work=$(mktemp -d /root/kvn-v5-install.XXXXXXXX)
  cd "$work"
  archive=kvn-portal-v5-installer.tar.gz
  curl --disable --fail --location --proto '=https' --proto-redir '=https' \
    --connect-timeout 10 --max-time 120 -o "$archive" \
    "https://github.com/artemiygaer/kvn-portal/releases/download/$tag/$archive"
  printf '%s  %s\n' "$sha" "$archive" | sha256sum --check --strict
  tar -xzf "$archive" --no-same-owner --no-same-permissions
  bash v5/install/install.sh
)
```

Мастер спросит каталог (по умолчанию `/root/portal`), предложит IP, запросит DNS-имена, логин,
пароль, порт и путь панели. Пароль вводится без отображения. На итоговом вопросе можно отменить
установку без изменений. При прерывании не удаляйте настройки наугад:
сохраните состояние и обратитесь к подробной [инструкции](install/README.md).

Ссылка заработает только после публикации указанного v5-релиза; архив v4.2
для этой команды не подходит. SHA из того же непроверенного архива не является
независимым подтверждением его подлинности.

## Первый вход и сертификаты

До выпуска доверенного сертификата откройте с компьютера SSH-туннель:

```bash
ssh -N -L 127.0.0.1:8443:127.0.0.1:8443 USER@SERVER
```

Адрес панели — `https://localhost:8443/login`. Через доверенный SSH получите
публичный `/etc/kvn-v5/gateway/bootstrap.crt` и проверьте его отпечаток;
приватный ключ не копируйте. Не отключайте проверку сертификата в браузере.
Мастер пытается выпустить доверенные сертификаты каждого имени и публичного IP;
при ошибке повторите выпуск в панели «HTTPS». Выпуск
HTTP-01 требует публичного TCP/80. Публичная страница и админка используют
одни имена, но доступны соответственно на 443 и выбранном порту панели.

Первичная поддержка Certbot и офлайн-зависимостей описана в
[инструкции установщика](install/README.md#установка-из-github-releases).
Перед публичным использованием отдельно проверьте выдачу, цепочку и плановое
продление на непроизводственном стенде. HTTP/80 остаётся открытым для ACME.

## Модули, перенос и наблюдение

В «Модули» выберите подписанный архив с GitHub или загрузите его вручную,
затем установите и отдельно включите. Выключение закрывает принадлежащие
модулю порты и сохраняет конфигурацию; удаление пакета также не удаляет
пользовательские настройки. Нужные возможности ядра и зависимости проверяются
до запуска. WireGuard и AmneziaWG независимы; новые конфигурации AWG — 3.1.
Текущий кандидат умеет подготавливать зависимости выбранного подписанного
модуля через панель. Настройка всех модулей и проверка установки на обеих
версиях Debian ещё не завершены; кандидат пока не готов к выпуску.

Экспортируйте `.kvn` в старой панели, перенесите архив и в v5 откройте
«Пользователи VPN → Импорт и экспорт .kvn». Сначала проверьте отчёт, затем
подтвердите импорт; пароли и архив передавайте по защищённому каналу. После
импорта установите и включите нужные модули отдельно.

Раздел «SSH и процессы» показывает текущий снимок по запросу. История на
1/2/6/12/24 часа выключена по умолчанию; при явном отключении её база
удаляется. Аргументы команд и содержимое терминалов не сохраняются. Консоль
root также выключена по умолчанию и включается отдельно.

## Обновление и восстановление

Подписанные модули можно подготовить в панели из GitHub или локального
архива; подготовка и применение — разные действия. Обновление ядра v5 также
доступно в «Обслуживание → Обновление ядра»: загрузите пакет из GitHub либо
файл `kvn-portal-v5-update.tar`, дождитесь проверки и отдельно подтвердите
применение. При запуске панель может кратко отключиться. Если результат не
подтверждён, обновите страницу и при необходимости проверьте службу по SSH.

Аварийное обновление ядра по SSH использует три файла одного подписанного
выпуска и `python3 -m v5.core.maintenance core-update`; не распаковывайте их
поверх установленного проекта. Готовые команды, проверка подписи, откат,
резервная копия и сброс доступа приведены в
[подробной инструкции](install/README.md#обновление-ядра-v5).

История наблюдения не заменяет бэкап. Для VPN-пользователей храните
зашифрованный `.kvn` отдельно; приватная копия ядра содержит секреты и не
зашифрована автоматически. Храните её в защищённом хранилище.
