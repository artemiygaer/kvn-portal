# Подписанные модули KVN Portal-first

Чистая установка ядра не устанавливает ни одного модуля. «Скачать и проверить» и «Загрузить и проверить» приводят к одному верификатору. После проверки доступно отдельное действие «Установить выключенным». Проверка и установка пакета не загружают образ в Docker, не запускают VPN и не публикуют порты.

## Контракт

- Имена вложений GitHub: `kvn-module-<модуль>-<X.Y.Z>.tar.gz`. Источник фиксирован как `artemiygaer/kvn-portal`, принимаются стабильные релизы v5. API сообщает размер и SHA-256 файла; ссылка из ответа не используется. Перенаправление допускается только на заранее разрешённые HTTPS-хосты GitHub CDN.
- Один gzip-поток; USTAR с каноническими заголовками сборщика. В начале `manifest.json` и 64-байтовая `manifest.sig`, затем строго перечисленные в манифесте файлы. Подпись Ed25519 покрывает канонический JSON с версиями схем, датами UTC, размерами и SHA-256 каждого ресурса. Новый пакет действует максимум 366 дней. Закреплённый ключ не берётся из архива.
- Допустимы только `payload/notes.txt` (UTF-8, до 32 КиБ) и для контейнерного модуля необязательный `payload/image.tar` (до 512 МиБ). Общий сжатый лимит — 256 МиБ. Путь, тип и предел каждого ресурса назначает ядро; ссылки, extended-заголовки, выход за пределы, скрытые члены, скрипты, команды и mounts не поддерживаются.
- Для контейнерного модуля подписанный манифест задаёт SHA-256 образа в фиксированном репозитории; подготовка сообщает, есть ли офлайн-образ или потребуется сетевой preflight. Для host-модулей указаны проверки инструмента и ядра. Архив образа хранится как непрозрачный ресурс: допуск конкретного образа, проверка digest и параметры runtime — ответственность встроенного адаптера. Недопустимо загружать образ в runtime только потому, что расширение `.tar` прошло проверку.
- Результат подготовки действует до суток, дополнительно проверяется срок манифеста перед установкой. Прямой downgrade и подмена содержимого уже принятой версии запрещены даже после удаления. Откат возможен только к предыдущей установленной версии выключенного модуля. История и состояние меняются одной транзакцией SQLite; пользовательские настройки хранятся вне реестра.

## Подготовка к выпуску

Сторона издателя подписывает архив приватным Ed25519-ключом. Приватный ключ не передаётся порталу, не включается в архивы и не хранится в репозитории. Сборщик сам проверяет созданный архив и печатает его SHA-256:

```bash
python3 -m v5.packaging.build_module --module-id wireguard --version 1.0.0 \
  --expires-at '2027-02-01T00:00:00Z' --key /защищённый/ключ.pem \
  --publisher-pin v5/packaging/publisher.json \
  --output kvn-module-wireguard-1.0.0.tar.gz
```

Дата — пример: выберите допустимый срок выпуска. Для контейнерных модулей обязателен `--image-digest` (64 hex), `--image` добавляет офлайн-ресурс. Доверенный JSON содержит ровно два поля: `public_der` (публичный Ed25519 SPKI DER в lowercase hex) и `sha256` (отпечаток того же DER, lowercase hex). Передавайте его отдельным доверенным способом или включайте в проверенный установщик:

Параметр `--publisher-pin` сверяет публичный ключ с ключом подписи; при
несовпадении сборка отклоняется до замены ранее созданного файла.

```bash
python3 -m v5.tools.build_installer /каталог/артефактов --publisher-pin /проверенный/publisher.json
```

Для готовящихся выпусков v5 публичный пин находится в
[`publisher.json`](publisher.json); его SHA-256 указан внутри файла. Закрытый
ключ хранится отдельно от рабочей копии и Git. До публикации сохраните его
резервную копию в защищённом месте: без неё нельзя подписать последующие
обновления уже установленных порталов. Замена ключа требует отдельной
безопасной процедуры смены доверия, а не простого изменения этого файла.

Установщик кладёт файл в `/etc/kvn-v5/packages/publisher.json` с правами `0600`. Без настроенного пина портал не доверяет ни одному пакету. Никогда не берите пин из загружаемого модуля. Привилегированный обработчик запускается по Unix-сокету только для операции, проверяет UID веб-службы и не имеет доступа к Docker socket, TLS-ключам и паролям панели. Карточки читаются основным агентом без запуска обработчика и без записи в реестр.

Справка по используемым протоколам: [OpenSSL Ed25519](https://docs.openssl.org/3.0/man1/openssl-pkeyutl/#ed25519-and-ed448-algorithms), [GitHub Release Assets](https://docs.github.com/en/rest/releases/assets?apiVersion=2022-11-28), [активация сокетом systemd](https://www.freedesktop.org/software/systemd/man/latest/systemd.socket.html).
