# Доказательства пакетного контракта v5

Рабочие серверы и GitHub Releases не изменялись. Тестовые ключи генерируются в закрытом временном каталоге WSL и удаляются после прогона. Ни один тестовый ключ не включается в установщик по умолчанию.

| Критерий | Проверка в WSL |
|---|---|
| Один пакет через GitHub и загрузку | Настоящие Flask POST и Unix RPC; GitHub API и CDN отвечают на loopback TCP. Один SHA-256 подтверждён в обоих ответах. URL из метаданных не используется, ложный хост перенаправления отклонён. Это проверка транспорта и контракта, не публичного v5 asset. |
| Недостоверный или несовместимый архив | Проверены отсутствие подписи, посторонний ключ, подмена тела/архивного SHA, обрезанный gzip, лишний поток, просрочка, будущая дата, версия схемы и лимиты. Ошибочная подготовка не меняет установленные записи. |
| Безопасный архив | Отклоняются traversal, абсолютные пути, ссылки, PAX/sparse, распухший хвост, лишние члены, неподдерживаемые ресурсы и произвольные команды/mounts. Декодирование ограничено по сжатому и выходному размеру. |
| Транзакции | Подготовка оставляет список установленного пустым, установка выключена. Проверены обновление, запрет downgrade, откат к предыдущему, удаление и сохранение SHA отдельного файла конфигурации. Инъекция отказа записи журнала не оставляет частичной установки и не сжигает билет. |
| Запасной канал и зависимости | При HTTP 503 загрузка файла работает с той же подписью. Зависимости определяются встроенной схемой: фиксированный digest и онлайн-проверка либо подписанный офлайн-ресурс. Проверен план с обоими вариантами; проверка реального образа и его запуска относится к фазе адаптера. |

Изолированные Debian-прогоны отдельно от тестов WSL: `tests/v5/debian_core_e2e.py` и `tests/v5/packages_portal_e2e.py`. Второй сценарий использует реальный nginx на 8443, сокет systemd, отдельный web UID и архив больше 768 КиБ; тестовый сеанс разрешён только после проверки identity учебной VM. Публичная установка из GitHub остаётся гейтом фазы 14.

Контрольная сумма установщика `a6dc8278a4a9c79387f6c7bf30bf0c66f0988a7b7c059a0766a5f62bd046a215`; подписанный синтетический Xray-архив `43b6d03e107ba78707346f4726bef140f3f5dc19ec51e44fd18089ae80982d6e`.
