# Проверка установки пустого ядра v5

Стенд: чистые официальные Debian 12 и 13 genericcloud в QEMU внутри WSL, по одному vCPU и 1 ГиБ памяти. Все подключения к стенду — через локальные SSH-порты, рабочие серверы не использовались.

Артефакт: `kvn-portal-v5-installer.tar.gz`, SHA-256 `6dcb02fc45d49a71b1fc13988264f8da661eadffb0172001ce2f8c2297ce107e`. На каждой VM хеш проверен до распаковки. Пакеты Python, nginx и их зависимости пришли из репозиториев Debian; Docker, образы VPN, DKMS и туннельные инструменты не установлены. Логи — `output/v5-lab/phase2-install-r2-22053.log` (Debian 12) и `output/v5-lab/phase2-install-r2-22054.log` (Debian 13).

Подтверждено на обеих VM:

- Отмена мастера не изменила пакеты и постоянные unit-файлы. Фикстура признаков v4.2 отклонена до ввода пароля, её файлы сохранились.
- Установка по Enter создала `/root/portal` с пустым реестром. `/root` сохранил `0700`. Gunicorn не запущен от root и не может читать каталог установки или TLS-ключ. Docker socket недоступен.
- В области проекта открылся только `127.0.0.1:8443`; три службы ядра активны, штатный `nginx.service` не запущен. Неверный Unix UID и неизвестный метод RPC отклоняются.
- Вход с паролем из мастера прошёл по HTTPS с проверкой сертификата; сводка показала агент, CPU, RAM, диск, сеть, uptime и отключённую историю.
- Повторный запуск сохранил контрольные суммы состояния, настроек входа и закрытого TLS-ключа. Сами секреты и их значения в логи не выводились.
- После перезагрузки изменился boot ID, контрольные суммы сохранились, все три службы стартовали. Из WSL по SSH-туннелю получен HTTPS 200 с проверкой сертификата. Оба прогона exit=0: `output/v5-lab/phase2-reboot-22053.log`, `output/v5-lab/phase2-reboot-22054.log`.

Проверка передачи из GitHub отделена от проверки локального архива. Публичный v5-архив ещё не доступен. На чистой VM с `curl` после появления артефакта этот же сценарий умеет взять его напрямую: `python3 tests/v5/debian_core_e2e.py PORT ARCHIVE SHA256 --github-tag TAG --reboot`. Принимается только v5-тег фиксированного репозитория; несовпадение SHA-256 останавливает распаковку.

Команды из инструкции выполняются в автоматическом тесте без доступа к GitHub: настоящий Bash, `sha256sum` и `tar`, тестовый транспорт. Ошибка скачивания (22) и неверный SHA-256 (1) не распаковывают архив и не вызывают установщик; корректный архив проходит до вызова установщика. Команда отключает пользовательский `.curlrc` и разрешает только HTTPS для исходного URL и редиректов.
