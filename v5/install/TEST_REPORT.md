# Проверка установки пустого ядра v5

Исходный стенд фазы 2: чистые официальные Debian 12 и 13 genericcloud в QEMU внутри WSL, по одному vCPU и 1 ГиБ памяти. Все подключения к стенду — через локальные SSH-порты, рабочие серверы не использовались. Ниже отдельно описан повтор на кандидате v5.0.2.

Артефакт: `kvn-portal-v5-installer.tar.gz`, SHA-256 `6dcb02fc45d49a71b1fc13988264f8da661eadffb0172001ce2f8c2297ce107e`. На каждой VM хеш проверен до распаковки. Пакеты Python, nginx и их зависимости пришли из репозиториев Debian; Docker, образы VPN, DKMS и туннельные инструменты не установлены. Логи — `output/v5-lab/phase2-install-r2-22053.log` (Debian 12) и `output/v5-lab/phase2-install-r2-22054.log` (Debian 13).

Подтверждено на обеих VM:

- Отмена мастера не изменила пакеты и постоянные unit-файлы. Фикстура признаков v4.2 отклонена до ввода пароля, её файлы сохранились.
- Установка по Enter создала `/root/portal` с пустым реестром. `/root` сохранил `0700`. Gunicorn не запущен от root и не может читать каталог установки или TLS-ключ. Docker socket недоступен.
- В области проекта открылся только `127.0.0.1:8443`; три службы ядра активны, штатный `nginx.service` не запущен. Неверный Unix UID и неизвестный метод RPC отклоняются.
- Вход с паролем из мастера прошёл по HTTPS с проверкой сертификата; сводка показала агент, CPU, RAM, диск, сеть, uptime и отключённую историю.
- Повторный запуск сохранил контрольные суммы состояния, настроек входа и закрытого TLS-ключа. Сами секреты и их значения в логи не выводились.
- После перезагрузки изменился boot ID, контрольные суммы сохранились, все три службы стартовали. Из WSL по SSH-туннелю получен HTTPS 200 с проверкой сертификата. Оба прогона exit=0: `output/v5-lab/phase2-reboot-22053.log`, `output/v5-lab/phase2-reboot-22054.log`.

Повтор на кандидате 5.0.2: чистая Debian 12 в QEMU/WSL с 2 vCPU и 2 ГиБ
скачала установщик непосредственно из публичного предварительного выпуска
GitHub `v5.0.2-rc.1`. Заранее сохранённый SHA-256
`b29869e4b1b2922a2cf01631d58ddbac92906ae2f5ff6d114d754167a01f117a`
проверен до распаковки. Проверены отказ при обнаружении v4, отмена мастера,
установка, повторный запуск без изменения данных, вход с паролем мастера,
SSH-туннель и HTTPS с проверкой сертификата; exit 0. Текущий TCP/80 открыт
для HTTP-01 и обслуживает оба заданных имени, bootstrap-панель слушает
loopback:8443; Docker и модули отсутствуют. Предварительный выпуск не заменяет
финальный стабильный. При отдельной перезагрузке изменился boot ID, настройки
и ключ bootstrap не изменились; три службы, HTTP и SSH/HTTPS снова проверены.

Debian 13 отдельно установлена из побайтно совпадающего архива GitHub draft.
После восстановления прерванной VM проверены права, TCP/80 и HTTPS-вход с
повторно заданным синтетическим паролем; публичное скачивание на Debian 13
отдельно не проверялось.

На Debian 12 в QEMU с 1 vCPU и 1 ГиБ установка ядра 5.0.2 обновлена через
портал подписанным кандидатом 5.0.3: состояния и настройки сохранены,
службы работают, HTTPS и слушатели проверены. Обновлённый веб-unit сообщает
systemd о готовности после предварительной загрузки приложения; после этого
старый updater подтвердил готовность на данном стенде. TLS-шлюз после обновления
подготовлен через панель, запрос сертификата больше 4 КиБ принят и проверен.
Тестовый архив и SHA описаны в состоянии финального аудита; это ещё не
подтверждение готовности всего стабильного релиза.

Дополнительно чистая Debian 12 скачала предварительный выпуск
`v5.0.4-rc.1` непосредственно из публичного GitHub Releases и проверила
установщик по заранее заданному SHA-256 до распаковки. Проверены отказ поверх
v4.2, отмена мастера, интерактивная установка и повторный запуск без изменения
конфигурации, вход с паролем мастера, права, HTTPS через SSH-туннель и TCP/80;
модули и Docker отсутствовали (exit 0). RC не является стабильным выпуском.
Обновление 5.0.3 → 5.0.4 через HTTPS проверено отдельно на двух Debian 12;
настройки сохранены, результат applied подтверждён и службы работают.

Воспроизведение: `python3 tests/v5/debian_core_e2e.py PORT ARCHIVE SHA256
--github-tag TAG --reboot` одной строкой. Принимается только v5-тег фиксированного
репозитория; несовпадение SHA-256 останавливает распаковку.

Команды из инструкции выполняются в автоматическом тесте без доступа к GitHub: настоящий Bash, `sha256sum` и `tar`, тестовый транспорт. Ошибка скачивания (22) и неверный SHA-256 (1) не распаковывают архив и не вызывают установщик; корректный архив проходит до вызова установщика. Команда отключает пользовательский `.curlrc` и разрешает только HTTPS для исходного URL и редиректов.
