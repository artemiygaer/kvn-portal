# Чистая установка KVN Portal-first

Нужен отдельный Debian 12/13 с systemd. Это чистая установка, обновление поверх v4 не поддерживается. Новая установка не загружает Docker, драйверы и дополнительные модули. Состояние портала хранится в `/root/portal` по умолчанию. Код служб установлен отдельно в `/usr/local/lib/kvn-v5`: веб-процессу не нужен доступ к `/root`.

Базовые зависимости включают GnuPG для зашифрованного переноса `.kvn`. Обработка архива запускается по запросу и не включает дополнительные модули.

## Установка из GitHub Releases

Команды предназначены для выпущенного v5-тега с файлом `kvn-portal-v5-installer.tar.gz`. Возьмите точный тег и SHA-256 установщика из доверенного объявления о выпуске. Предварительные выпуски предназначены только для тестирования.

Выполните от root в интерактивном SSH-терминале. Если в минимальном Debian нет `curl`, заранее установите `curl` и `ca-certificates` из штатного репозитория Debian. Не подставляйте архив v4.2.

```bash
(
  set -eu
  umask 077
  read -r -p 'Тег v5: ' tag
  read -r -p 'SHA-256 установщика: ' sha
  [[ "$tag" =~ ^v5\.[0-9]+\.[0-9]+(-[A-Za-z0-9.-]+)?$ ]]
  [[ "$sha" =~ ^[0-9a-fA-F]{64}$ ]]
  work=$(mktemp -d)
  cd "$work"
  archive=kvn-portal-v5-installer.tar.gz
  curl --disable --fail --location --proto '=https' --proto-redir '=https' -o "$archive" \
    "https://github.com/artemiygaer/kvn-portal/releases/download/$tag/$archive"
  printf '%s  %s\n' "$sha" "$archive" | sha256sum --check --strict
  tar -xzf "$archive" --no-same-owner --no-same-permissions
  bash v5/install/install.sh
)
```

Для подготовленного локального архива проверка SHA-256 и запуск те же. Из проверенного дерева исходников: `bash v5/install/install.sh`. Мастер предлагает обнаруженный публичный IP, спрашивает имена сервера, логин и пароль администратора, порт и путь панели. Пароль вводится без эха и не передаётся в параметрах процесса. Ответ «нет» на итоговый вопрос ничего не устанавливает.

После установки мастер пытается выпустить сертификаты Let's Encrypt для указанных имён и публичного IP без email. Для имён нужны правильные DNS-записи, для всех сертификатов — доступ извне к TCP/80. Certbot устанавливается из закреплённых wheels PyPI. Если выпуск не удался, остаётся аварийный вход через SSH-туннель, а сертификат можно выпустить позднее. В уже установленной панели Certbot при необходимости добавляется отдельно от root:

```bash
apt-get install --no-install-recommends python3-venv
cd /usr/local/lib/kvn-v5
/usr/bin/python3 -m v5.core.tls.provision
```

Без доступа к PyPI передайте `--wheels /абсолютный/каталог`: хеши проверяются и в этом режиме. Затем откройте «Сертификаты HTTPS». Для проверочного и публичного выпуска доступны отдельные результаты; для HTTP-01 нужен доступ извне на TCP/80 и правильный DNS. Не переносите сертификаты проверочной CA на публичный вход.

Email для регистрации ACME необязателен. Без него может быть затруднено
восстановление учётной записи. Let’s Encrypt не отправляет письма об
истечении сертификатов; контролируйте сроки и автоматическое продление в панели.

## Первый вход

Пока не настроен доверенный TLS, панель слушает только `127.0.0.1:8443`. Откройте отдельный SSH-туннель с вашего устройства:

```bash
ssh -N -L 127.0.0.1:8443:127.0.0.1:8443 USER@SERVER
```

Через уже проверенное SSH-соединение получите сертификат `/etc/kvn-v5/gateway/bootstrap.crt` (доступен root), проверьте его отпечаток и используйте его только для проверки `localhost`/`127.0.0.1`. Приватный ключ копировать не нужно. Адрес входа: `https://localhost:8443/login`. Не обходите проверку сертификата.

В разделе «Модули» архив можно получить из GitHub или загрузить вручную. В обоих случаях портал проверяет доверенную подпись. Установка отдельной кнопкой оставляет модуль выключенным. Выпущенный установщик может содержать публичный ключ издателя; сборка без ключа не примет ни одного пакета. Подробнее — [контракт модулей](../packaging/README.md).

Перенос: «Пользователи VPN → Импорт и экспорт .kvn». Загрузите зашифрованный архив, проверьте отчёт и отдельно подтвердите. Добавление сохраняет ключи назначения; восстановление общих ключей требует пустой цели. Установите, настройте и включите нужные модули отдельно — импорт не запускает службы. OpenConnect, сертификаты и настройки сети не переносятся. Откат доступен в том же сеансе, пока цель не изменилась.

Повторный запуск с тем же каталогом не меняет учётные данные, TLS-ключ и реестр. Если установка прервалась после начала записи, не удаляйте данные и не запускайте очистку наугад: проверьте `journalctl -u kvn-v5-agent -u kvn-v5-web -u kvn-v5-gateway` и сохраните `/root/portal` и `/etc/kvn-v5` для диагностики.

Раздел «Журнал» показывает до 40 последних событий за сутки по выбранному источнику. Для операций видны действие, результат и модуль, если он известен. Для служб — только время и приоритет. Никаких тел запросов, конфигураций или сырого вывода в браузер не передаётся. Для подробной диагностики используйте SSH и `journalctl -u ИМЯ-СЛУЖБЫ`.

## Приватная копия и восстановление доступа

Выполните от root по SSH:

```bash
cd /usr/local/lib/kvn-v5
python3 -m v5.core.maintenance backup
python3 -m v5.core.maintenance verify ИМЯ_АРХИВА SHA256
```

Команда печатает путь и SHA-256. Для проверки укажите имя файла без пути и сохранённый SHA-256. Копии находятся в `/root/portal/backups` (каталог 0700, архивы 0600); для другого каталога установки добавьте `--install-dir /root/ИМЯ` перед подкомандой. В архиве хеш пароля, ключ сессий и приватные TLS-ключи: он не зашифрован. Храните его только в закрытом или зашифрованном хранилище. Копия содержит конфигурацию ядра и активные TLS-пары, но не учётную запись ACME, VPN-пользователей, реестр или образы модулей. Пользователей сохраняйте отдельно в зашифрованном `.kvn`.

Если пароль потерян:

```bash
cd /usr/local/lib/kvn-v5
python3 -m v5.core.maintenance reset-admin --login admin
# Или взять имя администратора из копии и задать новый пароль:
python3 -m v5.core.maintenance reset-admin --from-backup ИМЯ_АРХИВА SHA256
```

Пароль вводится дважды без эха. Команда меняет только настройки web, перезапускает веб-службу и проверяет аварийный HTTPS-вход. Прежние пароли и сессии перестают действовать. Конфигурация nginx, TLS и VPN не переписывается; `--from-backup` берёт из копии только имя администратора. Если веб-служба не отвечает, оставайтесь в SSH и проверьте `journalctl -u kvn-v5-web -u kvn-v5-gateway`.

## Обновление ядра v5

Обновление ядра отдельно от модулей. Оно требует уже установленное ядро v5 и закреплённый ключ издателя `/etc/kvn-v5/core/publisher.json`. Штатный подписанный установщик закрепляет его при чистой установке. Если ключ не установлен, получите проверенный ключ издателя по независимому доверенному каналу; не используйте ключ из непроверенного обновления.

В панели откройте «Обслуживание → Обновление ядра». Выберите стабильный релиз
GitHub либо вручную загрузите `kvn-portal-v5-update.tar`. После проверки
подписи, версии и состава появится отдельная кнопка применения. Во время
переключения панель может кратко отключиться; при сомнительном результате
обновите страницу и воспользуйтесь восстановлением через SSH ниже.

Выберите точный стабильный тег, на котором опубликованы все три файла. В SSH под root:

```bash
(
  set -eu
  umask 077
  read -r -p 'Стабильный тег v5: ' tag
  [[ "$tag" =~ ^v5\.[0-9]+\.[0-9]+$ ]]
  work=$(mktemp -d /root/kvn-core.XXXXXXXX)
  for name in kvn-portal-v5-installer.tar.gz kvn-portal-v5-core.json kvn-portal-v5-core.sig; do
    curl --disable --fail --location --proto '=https' --proto-redir '=https' \
      --connect-timeout 10 --max-time 120 -o "$work/$name" \
      "https://github.com/artemiygaer/kvn-portal/releases/download/$tag/$name"
  done
  cd /usr/local/lib/kvn-v5
  python3 -m v5.core.maintenance core-update "$work"
)
```

Для локального обновления положите те же файлы в один закрытый каталог, передайте абсолютный путь в `core-update`. Не распаковывайте их поверх установки. Команда проверяет Ed25519, SHA-256, версию, состав архива и совместимость служб, затем переключает код. Пока идут операции с TLS, пакетами или переносом, обновление откладывается. Панель и локальный агент ненадолго остановятся; nginx, VPN и данные не перезапускаются и не заменяются. Результат подтверждается через доверенный HTTPS и локальный RPC.

Если выбран нестандартный каталог установки, добавьте `--install-dir /root/ИМЯ` перед `core-update` и `core-recover`.

При прерванном обновлении из SSH выполните `cd /usr/local/lib/kvn-v5 && python3 -m v5.core.maintenance core-recover`. Если новый код не позволяет запустить команду, попробуйте её из сохранённого дерева `/usr/local/lib/.kvn-v5-core/pending/tree`. Для явного возврата к предыдущей успешной версии используйте `core-recover --previous`. Хранится одна предыдущая версия кода; приватная копия конфигурации создаётся отдельно.

Сборка издателя: `python3 -m v5.tools.build_installer КАТАЛОГ --version 5.0.0 --publisher-pin ПУБЛИЧНЫЙ_PIN --signing-key ЗАКРЫТЫЙ_КЛЮЧ`. Закрытый ключ остаётся на машине издателя; для ядра на GitHub размещаются три исходных файла выпуска и их единый пакет `kvn-portal-v5-update.tar` для панели.

## Временная root-консоль

На чистой установке консоль выключена: нет активных сокетов, фоновых служб и отдельного сетевого порта. Для временного включения выполните по SSH от root:

```bash
apt-get install --no-install-recommends python3-websockets
systemctl start kvn-v5-console-web.socket
```

Заново войдите в панель, откройте «Обслуживание → Консоль root» и введите системный пароль root. Заблокированный, пустой или истёкший пароль не принимается; если root вход с паролем не настроен, используйте SSH. Не включайте парольный вход в SSH ради этой функции. Терминал ограничен 10 минутами и сеансом панели; пароли, нажатия и вывод не пишутся в журнал панели.

Отключение по SSH: `systemctl stop kvn-v5-console-web.socket`. Это закрывает WebSocket и останавливает все текущие PTY. После перезагрузки временное включение не сохраняется.
