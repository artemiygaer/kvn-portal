# SSH и процессы

Живой снимок создаётся только при обращении администратора к `/observability`.
Logind подтверждает удалённый SSH-вход; процесс и TCP-сокет сопоставляются по
идентичности root-процесса sshd, владельцу сокета и IP. При неоднозначности
счётчики не назначаются. Если logind недоступен, запасной источник `who`
используется только при подтверждении владельца TTY, цепочки процессов sshd и
сокета с тем же IP. Если `who` не содержит записей, допустима проверка TTY в
`/dev/pts` при том же подтверждении ancestry и сокета. Этот список помечается
неполным. На одном TCP-соединении может быть несколько SSH-каналов:
показанный объём относится ко всему соединению, а не к конкретной команде.
Счётчики TCP и `/proc` могут быть недоступны — это отображается как «нет данных».

Для определения владельца TCP выделен systemd socket с правами `0600` и
короткоживущий помощник `kvn-v5-socket-observer@.service`. Только он получает
`CAP_SYS_PTRACE` и выполняет фиксированный `ss`; порталу и обычному агенту эта
capability не выдаётся. Вывод помощника не попадает в журнал и наружу не
выдаётся: агент возвращает только разрешённые поля. Аргументы процессов,
переменные окружения и ввод/вывод терминалов не собираются. Нельзя использовать
этот интерфейс для выполнения команд.

Сбор истории по умолчанию выключен. Включение запускает отдельный
`kvn-v5-observer.service`; каждую минуту сохраняется ограниченный снимок в
root-only `/var/lib/kvn-v5/observability`. По мере сбора данные старше 24 часов
удаляются; хранилище ограничено 1441 снимком и 32768 страницами SQLite
(обычно до 128 МиБ при странице 4 КиБ). При отключении через портал сборщик останавливается, а его история
удаляется целиком; другие данные не затрагиваются. Сбор не возобновляется после
перезагрузки, если был выключен. Окна 1/2/6/12/24 часа показывают до 24
равномерно выбранных снимков, интервалы без данных и изменения сессий, выявленные
между соседними полными снимками. Это не точный аудит входов и выходов.
После смены идентификатора загрузки события не связываются между разными
запусками, а интервал отмечается как неполный; сам идентификатор порталу не
передаётся.

Сеть сервера — сумма счётчиков интерфейсов, кроме loopback; мосты и veth могут
давать двойной подсчёт. Скорость появляется после двух успешных замеров; при
сбросе счётчика показывается «нет данных». История не предназначена для
долговременного мониторинга или учёта трафика по каждому пользователю.

Проверки: `python3 -m unittest -v tests.v5.test_observability`; лабораторные
сценарии Debian находятся в `tests/v5/observability_*_lab_e2e.py` и допускают
только закреплённую тестовую VM. Измерения TCG/QEMU не являются нормативом для
реальных серверов.
