# Доказательства фазы 3: TLS, HTTP-01 и сайт

Внутренние проверки выполнялись на непроизводственных Debian в QEMU внутри
WSL с сетевыми пробросами на loopback. Внешний стенд описан отдельно ниже.
Приватные ключи и данные ACME-аккаунта в отчёт не включены.

| Проверка | Подтверждённый результат | Журнал |
|---|---|---|
| Debian 13, чистая установка r1 и reboot | Два DNS-имени и IP на TCP/80: HTTP-01, 308, 421, запрет POST и симлинков. Админка через SSH-туннель, состояние и TLS-ключ после reboot | `output/v5-lab/phase3-http01-debian13.log` |
| Debian 12, nginx и системный reload | Два отдельных DNS-сертификата и IP SAN без SNI; HTTPS 200 на 443/8443 с проверенной тестовой CA из WSL. Перекрёстный SNI/Host отклоняется, 443 не открывает админские пути. Отказ просроченной пары, возврат сайта и реальный rollback без смены PID master nginx | `output/v5-lab/phase3-tls-debian12-reuseport.log` |
| Debian 13, приложение через настоящий HTTPS | Вход по паролю подтвердил чистый прогон. В повторе в изолированной VM использована синтетическая сессия: multipart >4 КиБ, CSP sandbox, publish/reset через Unix RPC, обработка очереди `.path` и успешный запуск `renew.service` без lineages. Те же проверки прошли после reboot. Эта проверка не изображает реальное автоматическое продление | `output/v5-lab/phase3-debian13-full.log`, `output/v5-lab/phase3-debian13-full-retry.log` |
| Debian 12, Certbot offline | Certbot 5.9.0 на Python 3.11, 18 закреплённых wheels, проверка хешей и `pip check`, повтор без смены окружения | `output/v5-lab/phase3-certbot-debian12-retry.log` |
| Debian 13, Certbot offline | Certbot 5.9.0 на Python 3.13, 18 закреплённых wheels, проверка хешей и `pip check`, повтор без смены окружения, exit=0 | `output/v5-lab/phase3-debian13-full-retry.log` |

Локальный сценарий [Pebble](https://github.com/letsencrypt/pebble) завершился с exit=0: настоящий HTTP-01 и отдельные проверочный выпуск, активация и переиздание для двух DNS и IP. После staging `nginx.conf` не изменился; новые пары проверены по цепочке на 443/8443, master nginx не сменился. Наблюдатель TCP/80 из WSL получил 239 корректных ответов 308 и 0 ошибок. Журналы: `output/v5-lab/phase3-pebble-debian12.log`, `output/v5-lab/phase3-http80-watch.log`. Бинарники v2.10.1 проверяются по хешам в `tests/v5/pebble_e2e.py`, службы слушают только loopback гостя, тестовый корень не добавляется в системное доверие. У тестового переиздания намеренно форсируется окно; внешний плановый renew не засчитывается.

[Внешний ACME-прогон](EXTERNAL_TEST.md): на Debian 13 проверены staging и
публичный выпуск без email для двух DNS-имён и IP. Для всех трёх идентичностей
цепочка и SAN проверены с WSL на 443/8443; внешний стенд дополнительно проверил
DNS, изоляцию портала и разные сертификаты. Первые DNS/IP-пары проверены до и
после reboot. Принудительное переиздание этих двух пар применено штатной
службой; таймер активен после reboot. Плановый запуск таймера выполнил проверку
всех трёх идентичностей, но сертификаты ещё не требовали продления. Естественная
замена по сроку пока не подтверждена. DNS-резолвер WSL возвращает адреса локального proxy, поэтому
общий публичный пробник с проверкой DNS запускался на самом стенде, а отдельная
проверка цепочки с WSL подключалась непосредственно по публичному IP.
На стенде уже работал отдельный контейнер, поэтому это не доказательство
установки на пустую ОС. Проверка загрузки из опубликованного архива v5
остаётся обязательной.

Для проверки границы с VPN на чистом стенде подтверждено отсутствие VPN-модулей, Docker и VPN-портов до/после reload; контроллер TLS перезагружает только шлюз ядра. Повтор с активным VPN требуется на фазах сетевой интеграции. WSL: 61 тест, architecture/docs, compileall, diff check — exit=0.
