# TLS публичного входа v5

- У каждого зарегистрированного имени свой сертификат с одним точным DNS SAN. Прямой вход по IPv4/IPv6 использует отдельный IP SAN; wildcard и совпадение только по CN не принимаются.
- TCP/80 отдаёт нейтральную публичную страницу и токены HTTP-01 только для зарегистрированных имён и IP. TCP/443 отдаёт ту же страницу при наличии сертификата. Панель на этапе первичной настройки остаётся на loopback:8443; самоподписанный bootstrap-сертификат не попадает на публичный вход.
- Для выпуска IP через webroot нужен Certbot 5.4.0 или новее. Используется профиль `shortlived` и отдельные каталоги/lineage для staging и production. Источник: [Let’s Encrypt — сертификаты IP в Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot/).
- Кандидат проверяется по SAN, сроку, цепочке и ключу до записи. Пара сохраняется в одном закрытом неизменяемом поколении. При применении конфигурации сначала проверяется кандидат, затем новый слушатель; при отказе восстанавливается прежняя конфигурация и проверяется её ответ.

В «Сертификаты HTTPS» выбирайте имя и центр: Let’s Encrypt (публичный по
умолчанию, отдельно доступен проверочный) или ZeroSSL (публичный, только DNS).
IP-сертификаты по-прежнему выпускает только Let’s Encrypt. Проверочный выпуск
не заменяет активную пару. Таймер дважды в сутки проверяет продление через тот
центр, который выпустил активный сертификат. Для ACME используется Certbot
из отдельного окружения `/usr/local/lib/kvn-v5-acme/`.

## Подключить ZeroSSL

1. В [кабинете ZeroSSL](https://app.zerossl.com/) откройте **Developer → EAB Credentials → Generate**. Нужны **EAB KID** и **EAB HMAC key**, а не ключ REST API. [Инструкция ZeroSSL](https://zerossl.com/documentation/acme).
2. Выполните от root по SSH:

   ```bash
   cd /usr/local/lib/kvn-v5
   python3 -m v5.core.tls.zerossl
   ```

   Команда привязывает аккаунт один раз и не выпускает сертификаты. Введите
   EAB в терминале без эха, не передавайте его через аргументы, чат или портал.
   Сохраняется закрытый аккаунт Certbot; EAB не нужен для дальнейших продлений.
3. Обновите страницу «Сертификаты HTTPS». Выберите нужное DNS-имя и
   **ZeroSSL — только DNS-имена**, запустите выпуск и проверьте результат.
   Нужен доступ извне к TCP/80. Если вы ограничиваете выпуск через DNS CAA,
   разрешите `issue "sectigo.com"` для имени. [Справка ZeroSSL о CAA](https://help.zerossl.com/hc/en-us/articles/360060119753-Invalid-CAA-Records).

Само обновление портала и привязка аккаунта не меняют действующие сертификаты.
При неудачном выпуске или активации текущая пара сохраняется. Для смены центра
выберите его при новом выпуске для конкретного имени. Портал не переключает
центр автоматически при ошибке. Аккаунты и журналы ACME раздельны:
`/var/lib/kvn-v5/acme/public/` (Let’s Encrypt) и
`/var/lib/kvn-v5/acme/zerossl/` (ZeroSSL).

Там же доступна диагностика зарегистрированных DNS-имён и импорт доверенной
PEM-цепочки с незашифрованным ключом. Импорт проверяет SAN, срок, цепочку и
соответствие ключа до замены; ключ не попадает в журнал. Импортированные пары
автоматически через ACME не продлеваются: следите за сроком и заменяйте их
вручную либо явно запустите публичный выпуск ACME.

Если после обновления ядра панель сообщает, что шлюз не подготовлен к импорту,
дождитесь завершения обновления и нажмите «Подготовить HTTPS-шлюз». TLS-служба
применит конфигурацию с проверкой и откатом. При ошибке проверьте состояние и
журнал `kvn-v5-tls.service`; до устранения ошибки импорт недоступен.

Если выпуск не удался, используйте действующий IP-сертификат или аварийный
SSH-туннель. Методика внешней проверки: [тест ACME](EXTERNAL_TEST.md).
