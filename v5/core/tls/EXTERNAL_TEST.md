# Внешняя проверка TLS и ACME

Используйте отдельный непроизводственный Debian с доступными извне TCP/80, 443 и 8443, одним публичным IP и двумя тестовыми DNS-именами. Не изменяйте рабочий сервер. Оба имени должны указывать на стенд, в том числе корректно отрабатывать IPv6, если у них есть AAAA.

1. Установите ядро с `--with-acme` или добавьте Certbot отдельной командой из [инструкции](../../install/README.md). Откройте панель через SSH-туннель. На странице «Сертификаты HTTPS» отдельно запустите проверочный выпуск для обоих имён и IP. Зафиксируйте успешные результаты; staging не должен включать публичную пару.
2. Выпустите публичные сертификаты для тех же идентификаторов. С внешней машины (для разработки — WSL) запустите probe с IP и двумя DNS-именами стенда:

   ```bash
   python3 -m tests.v5.public_tls_probe --ip "$TEST_IP" --name "$TEST_DNS_1" --name "$TEST_DNS_2"
   ```

   Сохраните JSON как базовый снимок. Пробник проверяет системную цепочку доверия, точный SAN, один сертификат для 443 и 8443, разные сертификаты у разных имён, HTTP-01, публичную страницу на 80 и недоступность админских путей на 443. Он не использует обход проверки сертификата.
3. На стенде зафиксируйте активный `kvn-v5-tls-renew.timer` и журнал `kvn-v5-tls-renew.service`. Дождитесь фактического планового продления: срок и окно продления зависят от CA и профиля. Не засчитывайте `renew` с кодом 0, если сертификат не изменился; dry-run не заменяет публичный результат.
4. Повторите внешнюю команду с `--previous /путь/к/базовому-снимку.json`. Должны подтвердиться новые отпечатки и увеличившиеся сроки для всех идентификаторов. Сохраните снимки, журнал таймера и результаты staging отдельно. Не сохраняйте закрытые ключи, пароли и содержимое ACME-аккаунта.

Проверки на локальной CA в QEMU полезны для nginx, SNI и отката, но не засчитываются как этот прогон.
