# Сетевой жизненный цикл KVN v5

Сетевой план строится только из включённых установленных модулей. До применения проверяются конфликты имён и портов, занятые сокеты и доступность зависимостей. Имена, адреса и порты имеют типизированную схему; пакет не может добавить текст nginx, произвольное правило nftables или команду.

- TCP/80, TCP/443 и TCP/8443 принадлежат ядру. UDP/443 остаётся отдельным ресурсом для модуля. Без VPN-маршрутов nginx на TCP/443 обслуживает сайт напрямую и не загружает stream.
- Если есть VPN-маршруты, nginx на TCP/443 читает SNI без завершения TLS. Неизвестные или выключенные маршруты идут на локальный HTTPS-сайт; его внутренний порт не публикуется наружу. TCP/8443 не проходит через VPN-роутер. Имя сайта может делить TCP/443 только с явно выбранным self-steal Xray; это не включает self-steal по умолчанию.
- Поколения сертификатов и маршруты записываются в один проверенный `nginx.conf`. Перед заменой выполняется `nginx -t`, после reload проверяется ответ worker нужной ревизии. Сертификат не перерисовывает VPN-маршруты, а сетевая операция не меняет пары TLS.
- Для модулей с прямым listener отдельное правило NAT не нужно. Явный DNAT рендерится только в таблице `inet kvn_v5_ingress`, одной атомарной операцией. Внутренние порты такого backend закрыты от прямого входа. Одноимённая чужая таблица отклоняется; системные и Docker-таблицы не меняются. Одинаковая явно общая публикация остаётся до последнего владельца.
- При включении сначала запускается и проверяется backend, затем публикуется сеть. При отключении сначала снимаются маршруты, затем останавливается backend. Состояние SQLite фиксируется после проверки; конфиги и ключи не перезаписываются. Если процесс остановился между шагами, сверка восстанавливает последнее подтверждённое состояние, а версия пакета не меняется до сверки.

На пустой установке запуск `kvn-v5-reconcile.service` не создаёт БД и не ставит сетевые пакеты. При разборе сбоя root может запустить `systemctl restart kvn-v5-reconcile.service` и посмотреть `journalctl -u kvn-v5-reconcile.service`. Сверка не устанавливает зависимости и не запускает модуль, для которого нет встроенного адаптера. Для работы общего TCP/443 активному VPN-адаптеру нужен Debian-пакет `libnginx-mod-stream` и настроенный HTTPS-сайт; `nftables` требуется только для запланированного DNAT.

Справка: [nginx ssl_preread](https://nginx.org/en/docs/stream/ngx_stream_ssl_preread_module.html), [nftables: таблицы и NAT](https://netfilter.org/projects/nftables/manpage.html).
